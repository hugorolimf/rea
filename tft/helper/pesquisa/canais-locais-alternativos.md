## 1. Resumo executivo e veredito

1. **Existe um canal que entrega tudo o que o helper precisa sem ler tela: o Overwolf Game Events Provider (GEP).** Features `me` (`gold`, `xp` com `level`/`current_xp`/`xp_max`, `health`, `rank`), `store` (`shop_pieces` slot_1..slot_5 com marca "Sold"), `bench` (`bench_pieces` e `item_bench`), `board` (`board_pieces`), `match_info` (`round_type` com estágio, `round_outcome`, `opponent`), `roster` e `carousel`. [DOC] + [MEDIDO]
2. **Prova local de que funciona em Set 18 nesta máquina:** o banco SQLite do app TFTAcademy (`%APPDATA%\TFTAcademy\tft-events.db`) tem uma partida de 2026-09-11 (queue 1100, `set_number` 18) com eventos `me.gold`, `me.xp`, `store.shop_pieces` (IDs `DA_18_*`, "Sold" após compra), `bench.bench_pieces`, `bench.item_bench`, `board.board_pieces`, `match_info.round_type` ("1-2", "PVE"). [MEDIDO]
3. **O Overwolf foi instalado ontem à noite e o GEP já rodou no cliente dedicado `TFTClient-Win64-Shipping.exe`** (logs de 2026-10-10 00:00 a 00:27): `gep_tft.dll` carregada no processo do TFT, "tft plugin loaded", eventos `me.xp` (nível 1 → 2) registrados, Mobalytics Desktop registrou `onInfoUpdates2` e `onNewEvents`. [MEDIDO]
4. **Mas o GEP não é uma API local para Node.** Só se consome por dentro de um runtime Overwolf: (a) app Overwolf nativo (JS em CEF; exige "whitelist" de desenvolvedor para app não publicado), ou (b) app **ow-electron** (Electron com pacotes Overwolf; a main process é Node e expõe `app.overwolf.packages.gep`). Não há socket/porta pública do Overwolf para processos externos. [DOC]/[NÃO ENCONTREI] socket externo
5. **Nenhum outro canal legítimo entrega loja, banco ou ouro.** Live Client Data API (2999) não existe para o TFT do cliente Unreal; LCU/Riot Client só trazem lobby/sessão/pós-jogo; API oficial da Riot (spectator-tft-v5, tft-match-v1) não traz economia; não há replay de TFT; UI Automation retorna zero elementos; ETW não tem provedores do jogo.
6. **Risco de política independente do canal:** a página da Riot para TFT diz que apps não podem "make suggestions based on the player's current game state" e não aprova "Apps that provide dynamic, real-time information" (ver `07-ferramentas-e-regras-da-riot.md`). O GEP resolve o problema técnico, não o de política. Além disso, `augments` do GEP é proibido pela própria Overwolf, e `item_bench`/`opponent_board_pieces`/`match_stats.board_players` expõem dados de rivais, que a Riot não aprova rastrear.
7. **Incerteza de longo prazo:** não se sabe como o GEP lê os dados do TFT (código em DLL injetada, strings cifradas; Overwolf diz que o "como" é IP deles). Desde 2026-10-06 a Riot bloqueia por padrão acesso à memória por apps desconhecidos; ferramentas "known and currently approved" têm carência até **abril de 2027**. O aviso não cita Overwolf. [FATO-RIOT] + [INFERÊNCIA]

### 2.1 O que o TFTAcademy gravou (amostra de formato, partida de 2026-09-11, ~58 s)

Contagem por chave na única partida do banco: `battle_stats` 27, `item_bench` 13, `bench_pieces` 5, `gold` 4, `round_type` 3, `shop_visible` 3, `shop_pieces` 3, `board_pieces` 2, `player_status` 2, `xp` 1, `opponent_board_pieces` 1, mais eventos `match_start/round_start/round_end/battle_start/battle_end`.

Formatos observados (valores reais, truncados):

- `me.gold`: texto `"2"`, `"1"`; também `{}` no início e no fim (reset).
- `me.xp`: `{"level":2,"current_xp":0,"xp_max":2}` (string JSON; só emitido quando muda).
- `store.shop_pieces`: `{"slot_1":{"name":"DA_18_Sentry"},"slot_2":{"name":"DA_18_Rakan"},...,"slot_5":{"name":"DA_18_Akali_AD"}}`; compra vira `{"name":"Sold"}` no slot (ts 56 e 58 s). Vem junto de `shop_visible` "true"/"false".
- `bench.bench_pieces`: `{"cell_1":{"name":"DA_18_Varus","level":"1","item_1":"","item_2":"","item_3":""},...}` (chaves `cell_N`, não `slot_N`, apesar de o status público mostrar `slot_N`); `{}` quando vazio.
- `bench.item_bench`: array **de todos os 8 jogadores** `[{"summoner","tag_line","bench_items":[{"name":"DA_Consumable_ItemRemover","count":2}]}]`.
- `match_info.round_type`: `{"stage":"1-2","name":"PVE","type":"Minions_1","native_name":"Intro1"}`.
- `roster.player_status`: por jogador `{index, health, xp, localplayer, rank, tag_line}`.
- Precisão temporal: `timestamp` em segundos. `shop_pieces` apareceu no segundo 48 (início de 1-2), a compra no segundo 56, a segunda compra no segundo 58. Latência em milissegundos **não medida**. O arquivo foi modificado às 19:49, no mesmo minuto do último evento (19:49:02), o que indica gravação ao vivo. [INFERÊNCIA]

### 3.2 Como os dados são obtidos

- Oficial: Overwolf não documenta o método ("the How is our Magic", resposta de staff no fórum https://discuss.overwolf.com/t/how-does-overwolf-grab-game-data/1605, data não confirmada). [SECUNDÁRIO]
- Localmente: DLL de plugin (`gep_tft.dll`) carregada **dentro do processo do jogo** via injeção feita pelo `owe-client-x64.dll`/Overwolf, e o changelog fala em "DLL version with string encryptions" (GEP 281.x, jul/2025, https://dev.overwolf.com/docs/riot-games-gep-changelogs). [MEDIDO + DOC]
- Não sei se é leitura de memória, parsing de estruturas, ou hook de eventos. **Não encontrei declaração oficial.** Overwolf diz apenas que trabalha com publishers: "We work closely with game publishers to make sure all apps comply with their terms" e que o gamer não será banido (https://overwolf.com/our-commitment/, lido 2026-10-10). Isso é afirmação de fornecedor. [VENDOR]

### 3.4 Restrição de aprimoramentos

Citações literais da Overwolf (página TFT): "DO NOT include augment data support in your apps."; "This data can't be displayed on third-party apps and websites by any means as this is a violation of Riot TOS."; "Displaying this data can result in banning." Regra para o helper: **não assinar a feature `augments`** nem exibir lista de aprimoramentos ofertados vinda do GEP.

### 3.6 Latência, estabilidade e risco

- Latência: "real time" na doc; sem número. Medida local só em segundos (1 s de resolução na gravação do TFTAcademy). [NÃO ENCONTREI] ms
- GEP só entrega se a app assinou features cedo: "Late registration can cause missing events or unreliable data, especially if the app starts mid-match". `getInfo()` devolve estado atual quando o app abre no meio da partida.
- Eventos podem ser desativados a pedido do estúdio ("A request by the relevant game studio to disable this event").
- Quebra de GEP após patches é recorrente (vários "Fixed TFT Set 18 events" em set–out/2026).
- Risco de política: ver 3.3; risco de conta: não achei relato de punição a usuários de overlays GEP para TFT; a Riot "decide" e pode mudar.
- Efeito da regra de memória (abril/2027) é desconhecido para o GEP.

## 4. Canal 2: Riot Live Client Data API (porta 2999)

- Documentada só para LoL (`https://127.0.0.1:2999/liveclientdata/allgamedata`, certificado autoassinado). Não encontrei fonte dizendo que serve TFT. A Overwolf lista `live_client_data` para TFT, mas isso é uma feature GEP, não prova da porta. [NÃO ENCONTREI]
- Localmente a porta recusa conexão com o TFT Unreal (achado do orquestrador). Conclusão: **sem canal** neste cliente. Fontes: busca 2026-10-10; pkg.go.dev/github.com/Jonchun/leagueliveapi.

## 5. Canal 3: Riot Client e LCU

- **LCU** (`LeagueClientUx`): o esquema da versão 16.19 (https://raw.githubusercontent.com/dysolix/hasagi-types/main/swagger.json, baixado 2026-10-10) tem 1318 rotas; as de TFT são hub, passe, troves, planner, skill-tree, event-pve, cosmético, `/lol-end-of-game/v1/tft-eog-stats`, `/lol-match-history/v1/products/tft/{puuid}/matches` e spectate/replays genéricos. **Nenhuma rota de estado ao vivo** (ouro, loja, banco). O GEP lê o LCU para `lobby_info`, `game_flow`, `end_game.tft_end_game_stats` (fim de partida com board final). [MEDIDO + DOC]
- **Riot Client** (`RiotClientServices`, lockfile em `%LOCALAPPDATA%\Riot Games\Riot Client\Config\lockfile`): `GET /help` devolveu 1246 funções e 101 eventos; somente sessão de produto (`product-session/v1/sessions`, `external-sessions`, `LogsPath`), game-session, patch, chat. `external-sessions` carrega argumentos de lançamento do jogo (o log do Overwolf mostra que a linha de comando do TFT inclui `-GameId`, `-ServerIP`, `-ServerPort` e `-PlayerKey`); **não consultei** e **não usar** `PlayerKey` (credencial da sessão de rede). [MEDIDO]
- Status Riot: LCU "not officially supported for use with third party applications" (https://developer.riotgames.com/docs/lol); a descrição do schema da dysolix repete: "Don't try to expose data that Riot wants to hide". [FATO-RIOT / SECUNDÁRIO]
- Viabilidade Node: trivial (HTTPS + Basic auth do lockfile), risco baixo, mas só dá fase da partida, fila, `gameId`, resultado final.

## 6. Canal 4: APIs oficiais da Riot (web)

- `spectator-tft-v5`: `GET /lol/spectator/tft/v5/active-games/by-puuid/{puuid}` devolve `CurrentGameInfo`: `gameId, gameType, gameStartTime, mapId, gameLength, platformId, gameMode, gameQueueConfigId, observers.encryptionKey, participants[]` com `championId, perks, profileIconId, teamId, puuid, spell1Id, spell2Id, gameCustomizationObjects`. **Sem ouro, nível, XP, loja, banco ou itens.** Fonte: espelho https://github.com/chirpon9/riot-docs-mcp (copia do portal; confirmar no portal, que não renderizou para mim). [SECUNDÁRIO]
- `tft-match-v1`: pós-jogo. `tft-league-v1`, `tft-summoner-v1`, `tft-status-v1`: sem estado de partida.
- Acesso: produto TFT precisa ser registrado separadamente e o número de produtos é limitado (https://www.riotgames.com/en/DevRel/new-game-policy-and-tft-match-history). Latência de rede e atraso do spectator irrelevantes: não há campo de economia.
- **Veredito:** não serve ao helper em tempo real.

## 10. Caminhos NÃO considerados (apenas para constar)

Descartados por violarem anti-cheat/termos ou por estarem fora do pedido:

- **Leitura de memória** do `TFTClient-Win64-Shipping` (Cheat Engine, ReadProcessMemory, drivers). Desde 2026-10-06 a Riot bloqueia por padrão; Vanguard: "External tools reading memory will no longer work" (https://www.riotgames.com/en/DevRel/vanguard-faq, 2024-04-01); ToS 7.1 item 11 proíbe programas não autorizados.
- **Injeção de DLL/código** no processo do jogo (inclui imitar o que o Overwolf faz com `owe-client-x64.dll`/`gep_tft.dll`). Só o Overwolf, como fornecedor conhecido, faz isso.
- **Hooks** de D3D/Win32/EasyHook e interceptação de chamadas do jogo.
- **Captura de pacotes/rede** do jogo, proxy do tráfego, uso de `-ServerIP`/`-ServerPort`/`-PlayerKey` da linha de comando, ou do `PlayerKey`.
- **Modificar arquivos do jogo**, contornar o Vanguard, drivers de kernel.
- **Leitura de tela/OCR/visão computacional** (excluído pelo pedido; é a via do TFTSense).
- **Revelar informação oculta** (lobby revealers) e automação de ações (botting/scripting).

## 11. Regras de decisão acionáveis

- SE a meta é obter ouro/nível/XP/loja/banco sem ler tela ENTÃO usar o GEP (opção C, ou A como experimento rápido) PORQUE é o único canal que entrega esses campos e está documentado/ativo para o Set 18 [Overwolf TFT docs; status 28164/21570 estado 1; TFTAcademy DB medido].
- SE o usuário aceita registrar conta no Overwolf Console ENTÃO prototipar com ow-electron em Dev Mode (`OW_CLI_EMAIL`/`OW_CLI_API_KEY` ou `OW_DEV_KEY`) PORQUE a main process é Node e permite alimentar o `server.mjs` direto [ow-electron-packages-sample README, 2026].
- SE quer testar sem criar conta e o TFTAcademy está instalado ENTÃO abrir o Overwolf + TFTAcademy antes da partida e consultar `tft-events.db` em somente leitura, filtrando pelo `game_id` mais recente PORQUE já existe gravação ao vivo de gold/xp/shop/bench [medido em 2026-09-11].
- SE usar GEP ENTÃO chamar `setRequiredFeatures` para `me`, `store`, `bench`, `board`, `match_info`, `roster`(opcional) e **não** pedir `augments` PORQUE a Overwolf proíbe dados de aprimoramentos em apps de terceiros [Overwolf TFT docs].
- SE o app inicia no meio da partida ENTÃO chamar `getInfo(28164)` logo após habilitar PORQUE eventos anteriores se perdem [doc de GEP].
- SE `item_bench`, `opponent_board_pieces`, `board_spectate` ou `match_stats.board_players` forem recebidos ENTÃO descartar os dados de rivais, e usar apenas a entrada do jogador local (`summoner_name`/`tag_line` = Hero#BR7) PORQUE a Riot não aprova rastrear campeões/jogadas de oponentes e os valores incluem os 8 jogadores [Riot TFT dev doc via nota 07].
- SE o evento `shop_pieces` traz `Sold` ENTÃO tratar o slot como vazio e não como campeão PORQUE é o marcador de compra [GEP doc; medido].
- SE `me.gold` vem como `{}` ou `null` ENTÃO manter o último valor válido e marcar "reset" (início/fim de partida) PORQUE os dados são zerados no começo/fim [medido; doc: "Some Game Info fields are set to null at the end of a match"].
- SE a janela GEP falhar após patch (status do endpoint `game-events-status.overwolf.com/28164_prod.json` com `state` ≠ 1 ou chave ausente) ENTÃO cair para entrada manual e dados parciais de arquivos já usados, sem preencher valores PORQUE o provedor já teve correções recorrentes em set–out/2026.
- SE o objetivo é recomendar jogadas ao vivo ENTÃO considerar que o risco de política vem do que se mostra, não do canal PORQUE a Riot diz que um app não pode sugerir com base no estado atual do jogo [developer.riotgames.com/docs/tft, via nota 07].
- SE for tentar UI Automation, ETW ou títulos para economia ENTÃO não gastar tempo PORQUE retornam zero dados úteis para o TFT [README do tft, inspect-accessibility.ps1, logman].

## 13. Como isso se aplicaria a um assistente de decisão

Dados que o sistema receberia do GEP e como cada regra os usaria:

| Regra/uso                        | Dados do GEP                                                                               | Dados adicionais necessários                                                                                                                                            |
| -------------------------------- | ------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Juros e decisão de segurar/rolar | `me.gold`                                                                                  | estágio (`match_info.round_type.stage`), HP (`me.health`), streak (calcular de `round_outcome`)                                                                         |
| Nível alvo e custo de XP         | `me.xp.level`, `current_xp`, `xp_max`                                                      | tabela de odds por nível do patch 18.4 (estática)                                                                                                                       |
| Loja (quem comprar, o que rolar) | `store.shop_pieces` (+ `shop_visible`)                                                     | catálogo `DA_18_*` → nome/custo/traits (já no `catalog.json`); pool de cópias restantes (precisa de contagem do próprio jogador; scouting de rivais não deve ser usado) |
| Banco e fusão 3→2★/3★            | `bench.bench_pieces`, `board.board_pieces` (cópias e estrelas)                             | limite de banco (9)                                                                                                                                                     |
| Itens (combinar, guardar)        | `bench.item_bench` (só linha do jogador local), `item_select`, `picked_item`               | receitas de itens (já em `items.json`)                                                                                                                                  |
| Fase e tempo                     | `round_start/round_end`, `battle_start/end`, `round_type`                                  | mapa de estágios/PvE                                                                                                                                                    |
| Identidade                       | `me.summoner_name`, `roster.player_status[].localplayer`                                   | Hero#BR7 fixo (README)                                                                                                                                                  |
| Reconciliação                    | `getInfo()` na entrada tardia; status em `game-events-status.overwolf.com/28164_prod.json` | monitor de saúde do provedor                                                                                                                                            |

Estado de integração sugerido (sem alterar código agora): uma camada "fonte GEP" (SQLite do TFTAcademy ou POST do app Overwolf/ow-electron) que alimenta o mesmo modelo que hoje vem de `TFTEoGStats.json`, com cada campo marcado por origem e idade; GEP prevalece para ouro/nível/XP/loja/banco/itens, enquanto os arquivos locais continuam como respaldo do tabuleiro final. Campos de rivais e de aprimoramentos ficam desligados por configuração.
